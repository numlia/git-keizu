> Origin: フェーズ3 修正 L14 (dialog-ref-input-event-validation)
> Added: 2026-07-04T04:29:24Z
> Status: active
> Supersedes: -
> Signature: the validation handler of the text-ref input in `showFormDialog()` (`validateRefInput`)
> Target Path: `web/dialogs.ts:153-171`

A fix that extracts the text-ref input validation from an anonymous `keyup` listener into the named function `validateRefInput` and binds it to the `input` event in addition to `keyup`. R4.7 "Return to where it was started after a keyboard close or when the action completes" / A8.1-6. A menu item's `onClick` runs after `activateItem` has hidden the menu, so for the merge dialog, which called `showFormDialog` with `sourceElem = null`, `captureSession(null)` saw `activeElement === body` and kept `{ origin: null, source: null }`; after Escape / Dismiss / "Yes, merge", `restoreFocus(null, "keyboard")` returned `false` and focus fell to `body` (review finding round 2 G2. The public API of `web/keyboardNavigation.ts` is unchanged. The fixture registers `configureFocusContext` with row `M` inside `#commitTable` as `getActiveRow` in `beforeEach` (imported from the same module registry as `web/dialogs`), and opens the dialog after making `activeElement` the `body`.
