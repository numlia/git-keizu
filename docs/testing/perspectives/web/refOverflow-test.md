> Test File: `tests/web/refOverflow.test.ts`

A pure function that returns how many badges to keep from the start, given the outer badge widths, the limit B and the counter outer width for each count (implementation plan §3.4). Expected values are copied from the 8 rows of implementation plan §3.6 "Independent boundary inputs and expected results"; they are not produced with the production function. ## S8: Opening, closing and operating the list of hidden badges (double-click in the list forwarded to the owner)

> Origin: Feature 061-06 (light-spec-plan)
> Added: 2026-10-17
> Status: active
> Supersedes: S7
> Signature: `RefOverflowOptions.onRefDoubleClick: (event: MouseEvent, ref: HTMLElement) => void` (required readonly callback) / `private handlePopupDoubleClick(event: MouseEvent, popup: HTMLElement): void`
> Target Path: `web/refOverflow.ts:153-164` (`RefOverflowOptions`; `onRefDoubleClick` on line 161), `web/refOverflow.ts:696-726` (`openPopup`; registers `handlePopupDoubleClick` on line 708), `web/refOverflow.ts:762-770` (`handlePopupDoubleClick`)
> Test File: `tests/web/refOverflow.test.ts`

Perspectives for implementation plan §3.4 and §3.6 and finalized spec §4.2, AC-07, AC-09 and AC-10. TC-070 of S7 (inherited from S4) said "click / dblclick in the list both do nothing", but the contract changes so that a dblclick in the list is forwarded to the owner (the shared checkout handling in `web/main.ts`), so this section replaces S7. **TC-115 of S7 and TC-061 to TC-063, TC-065 to TC-069, TC-071 to TC-086 and TC-098 that S7 inherited from S4 are explicitly carried over to this section with unchanged expected results**, and their tests stay in describe `RefOverflowController hidden-badge list` with the same Case IDs. **Only the old TC-070 is replaced, by the new TC-116** (click is forwarded 0 times; dblclick is forwarded once, passing the original event and the copied badge as they are; 0 bubbles to the row and document; the list stays open). The keyboard contract of S6 stays active.

One dblclick listener is placed on the list container when it is created. It first stops propagation, and calls `this.options.onRefDoubleClick(event, ref)` once only when `this.popup === popup`, `event.target instanceof Element`, and the nearest `.gitRef` is an HTMLElement satisfying `popup.contains(ref)`. The event is not re-dispatched to the original element in the row. The listener is not added in `renderPopupItems` / `onRefCloned`. Click keeps the existing propagation stop. Choosing local / remote, the content of the Git request and resolving the `dataset` of the remote part belong to the owner (`web/main-test/01-rendering-03.md` S85) and are not in this table.

The fixture is the same `createController` as S4 / S7, with `onRefDoubleClick` as a `vi.fn()` spy. **The spy sends nothing, so 0 `postMessage` calls are not used as evidence that no checkout happens** (whether a checkout happens is verified on the owner side in S85). There is no DOM path from the list directly under body to the row, so bubble listeners are always observed on the document as well as the row. The existing document capture click that detects outside clicks is not included in what gets stopped.
