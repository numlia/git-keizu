## S1: reconcileRowTarget() pure recalculation of the operation target

> Origin: Feature 061-05 (light-spec-plan)
> Added: 2026-10-07
> Status: active
> Supersedes: -
> Signature: `export function reconcileRowTarget(previous: RowTarget | null, repo: string, hashes: readonly string[], head: string | null): RowTarget | null` (`RowTarget` has readonly `repo: string` / `hash: string` / `index: number`)
> Target Path: `web/keyboardNavigation.ts:158-176` (`reconcileRowTarget`)
> Test File: `tests/web/keyboardNavigation.test.ts`

Perspectives for implementation plan §3.4: "Deciding the target is a pure function that does not modify its inputs. It checks for a hash match first, and only when the target disappeared in the same repo does it clamp the old index to the end. A repo switch or no previous target gives HEAD / the first row, and an empty list gives null. The index is not used as an identifier." It never reads the DOM, and a describe with `// @vitest-environment node` confirms it can be called without `document`. The existing identifier of the working tree row (`UNCOMMITTED_CHANGES_HASH`) and stash hashes are treated as ordinary hashes, and it does not fetch unloaded targets or send requests. Return values are compared on all fields with `toEqual`, and `null` is compared directly with `toBeNull()`.

## S2: installKeyboardGuards() / isKeyboardActionBlocked() input protection for IME, repeat and matching keyup

> Origin: Feature 061-05 (light-spec-plan)
> Added: 2026-10-07
> Status: active
> Supersedes: -
> Signature: `export function installKeyboardGuards(root: Document): () => void` / `export function isKeyboardActionBlocked(event: KeyboardEvent): boolean`
> Target Path: `web/keyboardNavigation.ts:178-277` (`keyIdentity` / `isActionKey` / `isButtonTarget` / `withPendingKey` / capturing composition, keydown and keyup / `installKeyboardGuards` / `isKeyboardActionBlocked`)
> Test File: `tests/web/keyboardNavigation.test.ts`

Input protection at the end of implementation plan §3.4. `compositionstart` / `compositionend` and `keydown` / `keyup` on `document` are tracked in the capture phase, and the components and main read the same verdict. The verdict is "blocked" for `isComposing` or an active composition, for the `keyup` that matches a composition commit or cancel, and for `repeat` of action keys (Enter / Space / ContextMenu). It is not released immediately at `compositionend` but at the matching `keyup`. It does not call `preventDefault` on character input or arrows. The fixture is jsdom with an `<input>` and a `<button>` after `installKeyboardGuards(document)`. Each case asserts the return value of `isKeyboardActionBlocked` (`true` / `false`) directly, and also observes `defaultPrevented` and the number of `click` listener calls on the `button`.

## S4: beginFocusUpdate() / finishFocusUpdate() render restore with replacement tickets

> Origin: Feature 061-05 (light-spec-plan)
> Added: 2026-10-07
> Status: active
> Supersedes: -
> Signature: `export function beginFocusUpdate(root: HTMLElement): FocusUpdate \| null` / `export function finishFocusUpdate(update: FocusUpdate \| null): boolean` (`FocusUpdate` has readonly `origin: FocusOrigin` / `root: HTMLElement` / `generation: number` / `focusEpoch: number`)
> Target Path: `web/keyboardNavigation.ts:501-586` (`ownsPopupOrigin` 501-511, `withParkedKeys` 512-532, `beginFocusUpdate` 533-556, `finishFocusUpdate` 557-586. Tracking of focusin / pointerdown / window blur is 279-315)
> Test File: `tests/web/keyboardNavigation.test.ts`

The ticket approach of implementation plan §3.4. `beginFocusUpdate` returns a ticket only when real focus is inside the root, or inside an owned popup removed by the same replacement, right before the replacement, and advances the render generation for that root. `finishFocusUpdate` restores only for the same repo, the latest ticket and the same focusEpoch, when the webview has not blurred and the user has not moved to another element, and uses `focus({ preventScroll: true })`. The fixture is the same as S3; verification runs after registering `configureFocusContext` and `installKeyboardGuards`, and `HTMLElement.prototype.focus` is spied to observe its arguments too.
