> Test File: `tests/web/pathHighlight.test.ts`

Pure computation perspectives that verify the 9 rows of acceptance data in implementation plan §3.7 by exact match of `hashes`, `edgeKeys`, `boundaries` and `targetFound`. The standard fixture has the display order `N,M,A,B,U,R,X` and the relations `N→[M]`, `M→[A,B]`, `A→[R]`, `B→[R]`, `U→[R]`, `R→[]`, `X→[]` (each row has `stash: null` and `refs: []`, and the hashes are display identifiers). The expected `edgeKeys` do not call the product's `pathEdgeKey`; they are written as literal strings in the form `["子","親"]` (the same string as `JSON.stringify([childHash, parentHash])`). `hashes` / `edgeKeys` are compared with `toEqual` between `Set`s, and `boundaries` with `toEqual` on the array without sorting. Mode values are `Direct` / `AncestorsAndDescendants` / `FirstParent` / `AllAncestors` of the enum `PathHighlightMode`. DOM, SVG, translations and host messages are not touched (rendering belongs to `web/graph-test.md` S21, and the status bar to `web/pathHighlightController-test.md` S1).
