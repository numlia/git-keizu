Harness and fixture:

- `REPO = "/test/repo"`, `OTHER_REPO = "/test/other-repo"`. Branch A is `feature/a` with worktree `/tmp/wt-a`, branch B is `feature/b` with worktree `/tmp/wt-b`; both are built by `buildRefContextMenuItems` with a `sourceElem` that has the `head` class, `gitBranchHead = "main"` and `isMainWorktree: false`. Detached A is `/tmp/detached-a` and detached B is `/tmp/detached-b`, built by `buildDetachedWorktreeContextMenuItems(REPO, path)`.
- "Confirm A" renders A's menu with `showContextMenu`, clicks A's real removal item (branch: child of `More...`; detached: the last item) and then `#dialogAction` (Remove / Yes). "Recent removal item" is the item under the Recent label whose text is `Remove Worktree…`. The history passed to B's `showContextMenu` is the one actually updated by the confirmation (`viewState.repos[REPO].recentActions`), not a hand-written array.
- "Save request" and "removal request" are `vscode.postMessage` calls whose `command` is `saveRepoState` and `removeWorktree`. A real record also sends the save request, so the total number of messages is not expected to be 1. The call history is split immediately before each confirmation and each command is counted separately: every confirmation sends exactly one save request followed by one removal request (save `invocationCallOrder` < removal), and every Cancel / No / close adds 0 of each.
- "Normal part unchanged" means the rendered items after the Recent block, including the `More...` children, match the rendering of the same builder output without history (branch: `Remove Worktree…` stays in `More...` after `Rename Branch…` and `Delete Branch…`; detached: it stays last after the divider).
- TC-031 to TC-034 start with an empty history for `REPO`, so A's confirmation leaves `["ref.removeWorktree"]`.
