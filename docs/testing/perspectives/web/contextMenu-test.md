## S12: contextmenu from the launching key's keyup and right-clicks inside the menu

> Origin: Feature 061-05 (light-spec-plan) review fix
> Added: 2026-10-07
> Status: active
> Supersedes: -
> Signature: `trackKeyboardLaunch(target: HTMLElement, key: string): void` / `suppressFollowingContextMenu(event: Event): void` (suppresses once a `contextmenu` that targets something inside `launch.target` or inside `#contextMenu` / `ul.contextMenuSubmenu`) / `suppressLaunchKeyup(event: KeyboardEvent): void` (calls `preventDefault` once on the keyup with the same `key` as the launching key) / `hideContextMenuListener(event?: Event): void` (ignores a `contextmenu` that targets something inside the menu)
> Target Path: `web/contextMenu.ts:72-82` (`KeyboardLaunch.key`), `web/contextMenu.ts:406-447` (`isInsideMenu` / `suppressFollowingContextMenu` / `suppressLaunchKeyup` / `trackKeyboardLaunch`), `web/contextMenu.ts:687-690` (`trackKeyboardLaunch(sourceElem, event.key)` on a key launch), `web/contextMenu.ts:753-760` (`hideContextMenuListener`)
> Test File: `tests/web/contextMenu.test.ts`

The Windows side of R4.4 "open only once even when the key and the browser's contextmenu overlap". Blink fires the `contextmenu` from the ContextMenu key (VK_APPS) on keyup, targeting the element focused at that moment (the first `li` of the menu opened on keydown). The S9 TC-124 suppression swallows only targets inside `launch.target` (the origin), so this `contextmenu` reached the document `hideContextMenuListener`, closed the just-opened menu as `"outside"`, and focus fell to `body` (review finding round 2 G1). The fix is: (a) while a launch is pending, a `contextmenu` that targets something inside the menu / submenu is also swallowed once as the same key press, (b) the keyup with the same `key` as the launching key gets `preventDefault` once to stop the synthesis itself, (c) `hideContextMenuListener` does not treat a `contextmenu` that targets something inside the menu as an outside click. The contract that an independent right-click (preceded by `pointerdown` / `mousedown`) and a new keydown release the suppression, and keyup does not (round 1 F3), is kept. The fixture is the same as S9, and `hideContextMenuListener` is registered on the `document` `contextmenu` as in main.
