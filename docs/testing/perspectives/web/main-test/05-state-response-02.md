## S41: buildAuthorOptions() merging all authors ∪ selected authors

> Origin: フェーズ2 修正 M12 (author-dropdown-merge-options)
> Added: 2026-07-04T02:44:58Z
> Status: active
> Supersedes: -
> Signature: `function buildAuthorOptions(authors: string[], selectedAuthors: string[]): { options: { name: string; value: string }[]; selected: string[] }`
> Target Path: `web/main.ts:93-104`

This fix changes `buildAuthorOptions` to merge "the full author list ∪ the selected authors (only those not in `authors` are appended at the end)". It builds the options `[All Authors, ...mergedAuthors]` from `mergedAuthors = [...authors, ...selectedAuthors.filter((a) => !authors.includes(a))]`, and returns `selectedAuthors` as `selected` unchanged. This guarantees that an author selected in the filter does not disappear from the options even when it is not among the current author candidates.

## S42: loadCommits() unconditional rebuild of the Author dropdown

> Origin: フェーズ2 修正 M12 (author-dropdown-unconditional-rebuild)

> Status: active
> Supersedes: S16, S21, S23
> Signature: `public loadCommits(commits, commitHead, moreAvailable, hard, authors?)`
> Target Path: `web/main.ts:477-486`

This fix removes the `if (this.selectedAuthors.length === 0)` guard from `loadCommits` so the author dropdown is always rebuilt. `authorList` prefers `authors` (provided by the server); when it is not provided, it is computed from `commits` with deduplication and sorting. It is merged with `buildAuthorOptions(authorList, this.selectedAuthors)` (S41), and `authorDropdown.setOptions(options, selected)` is always called. This rebuilds the dropdown even while a filter is selected, and keeps the selection. It replaces the old S16 (list not updated while filtering) / S21 (skipped when `authorFilter !== null`) / S23 (not updated while a filter is selected).

## S43: loadAvatar() applying avatars by comparing raw emails in dataset.email

> Origin: フェーズ3 修正 L15 (avatar-raw-email-compare)
> Added: 2026-07-04T04:29:24Z
> Status: active
> Supersedes: -
> Signature: `public loadAvatar(email: string, image: string): void`
> Target Path: `web/main.ts:497-506`

This fix changes the matching of `.avatar` elements from `avatarsElems[i].dataset.email === escapeHtml(email)` to a comparison of raw emails, `avatarsElems[i].dataset.email === email`. `dataset.email` stores the raw email (L16 also removed the unescape on the reading side), so the old implementation compared `escapeHtml(email)` with the raw email, and for emails containing HTML special characters the avatar did not match and was not applied. `image` is still passed through `escapeHtml` when embedded into the `src` of `img`, as before.
