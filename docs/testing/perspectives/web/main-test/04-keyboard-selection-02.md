## S64: handleKeyboardShortcut() Arrow key preconditions, event control, and routing in file history mode

> Origin: Feature 060-02 (light-spec-plan)
> Added: 2026-09-28
> Status: superseded
> Superseded By: S71（[13-keyboard-accessibility-01.md](13-keyboard-accessibility-01.md)）
> Supersedes: S32, S33
> Signature: `handleKeyboardShortcut(e: KeyboardEvent): void` (Arrow branch. In history mode it calls `FileHistoryController.navigate(delta: -1 | 1, useExpandedCommit: boolean = false): string | null` as `navigate(delta, true)`)
> Target Path: `web/main.ts:1529-1550` (`handleFileHistoryArrowKey()`, the Arrow branch for history), `web/main.ts:1455-1504` (the IME guard, the call to the history branch, and the normal Arrow branch in `handleKeyboardShortcut()`)
> Test File: `tests/web/main.test.ts`

S32's "do not handle Arrow when details are closed" and S33's "do not consume the event when no move is possible" no longer hold while file history is highlighted or a fetch is pending. The S32 / S33 tables are left unchanged; all 9 cases are carried over into this section with a normal-mode precondition (TC-562 to TC-570), and routing for history mode is added. S29 to S31, S46, and S58 in `04-keyboard-selection-01.md` stay active and unchanged. Choosing the move target, current, the position display, and restoration belong to `web/fileHistory-test.md` S10, and drawing details after a key move belongs to `10-file-history-01.md` S66; they are not part of this table.

- Normal mode: `fileHistory.isActive()` and `fileHistory.isPending()` are both `false`
- History mode: one of highlight only (only `isActive()` is `true`), initial fetch pending (only `isPending()` is `true`), or switch pending while highlighted (both `true`)
- The controller stays under `vi.mock`, and the return value of `navigate` is controlled by the mock (default `null`). The table is `[h0, x1, h1, x2, h2]`
- "Consumed" means `preventDefault()` and `stopPropagation()` are each called once; "not consumed" means each is called 0 times
- "Details request" is a message with `command: "commitDetails"` passed to `vscode.postMessage`
- "Graph move" means the 4 methods `getFirstChildIndex` / `getFirstParentIndex` / `getAlternativeChildIndex` / `getAlternativeParentIndex`

## S65: handleEscape() priority chain and exiting file history

> Origin: Feature 060-02 (light-spec-plan)
> Added: 2026-09-28
> Status: superseded
> Superseded By: S72（[13-keyboard-accessibility-01.md](13-keyboard-accessibility-01.md)）

> Signature: `handleEscape(): void` (after the details stage, calls `FileHistoryController.exit(restore: boolean): void` as `exit(true)`)
> Target Path: `web/main.ts:1591-1625` (`handleEscape()`. The history stage is 1621-1624)
> Test File: `tests/web/main.test.ts`

The Esc order is `contextMenu → dialog → repoDropdown → branchDropdown → authorDropdown → ref一覧 → findWidget → expandedCommit → fileHistory`. S40 (handleEscape() priority chain) in `04-keyboard-selection-01.md` had details (`expandedCommit`) as the last stage, so this section replaces it (S40 with the same number in `08-request-queue-01.md` is out of scope). The S40 table is left unchanged, and all 8 cases are carried over with a not-highlighted precondition (TC-594 to TC-601). Each stage closes only its own UI and returns, and the Esc that closed an earlier stage does not exit history. The ref list stage itself remains covered by S58 of `04-keyboard-selection-01.md`, which stays active. Esc fires on a real keyup, and the controller stays under `vi.mock` with its state controlled by the mock. The real state of clearing and restoring belongs to `web/fileHistory-test.md` S8 and S10 (TC-099 to TC-102) and is not part of this table.
