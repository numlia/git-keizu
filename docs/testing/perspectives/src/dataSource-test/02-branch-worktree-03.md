## S47: getWorktrees() returns a collection, and pinned detached commits are fetched and merged

> Origin: Feature 052 (detached-worktree-display) (light-spec-plan)
> Added: 2026-08-08
> Updated: 2026-09-12
> Status: active
> Supersedes: S22
> Signature: `getWorktrees(repo: string): Promise<WorktreeCollection>` / `getCommits(repo, branches, maxCommits, showRemoteBranches, authors, commitOrdering)`
> Target Path: `src/dataSource.ts` (`getWorktrees()` and the pinned query / merge in `getCommits()`; to be updated to a line range after implementation)
> Test File: `tests/src/dataSource.test.ts`

A change that turns the return value and failure fallback of `getWorktrees()` from `WorktreeMap` / `{}` into `WorktreeCollection` / `{ branches: {}, detached: [] }`, makes `getCommits()` fetch worktrees first, fetches detached HEADs outside the normal display window with a separate `git log --no-walk=sorted` query (the pinned query), and merges them at the end of the normal commit list. The 2026-09-12 update added a rule: when the parent of a pinned commit is in the normal list, the pinned commit is inserted right before that parent (the earliest one if there are several). Left at the end, the child would come after its parent, `determinePath()` in `web/graph.ts` would never finish, and the webview would be stuck on "loading" (TC-364 to TC-366). The old S22 fixed the return value as a flat map and the failure fallback as `{}`, so it is superseded. The porcelain classification rules belong to `src/worktree-test.md` S2, the hash value range to `src/utils-test.md` S7 and label rendering to `web/main-test/01-rendering-02.md` S48. The composition of `--max-count` / order flag / branch arguments of the normal log itself belongs to the existing S21 and does not change.
