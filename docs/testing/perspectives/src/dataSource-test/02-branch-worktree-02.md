> Test File: `tests/src/dataSource.test.ts` / `tests/src/dataSource.git.test.ts`

A change that drops `git checkout -B <branch> <remote-branch>` and makes the operation safer in the order: ref validation → read-only existence check of the existing branch → `checkout --track -b`. The return value changes from `GitCommandStatus` to `CheckoutBranchResult` (`branchExists | invalidRef | completed`). The local path (`remoteBranch === null`) keeps the args `["checkout", branchName]` and only adds validation. Because `-B` leaves the scope, this supersedes the old S9 that assumed `-B`. The ref name rules themselves belong to `src/refValidation-test.md` S1, and the webview display to `web/messageHandler-test.md` S12.

## S42: preparePush() / getRemotes() resolving the push target

> Test File: `tests/src/dataSource.test.ts`

Perspectives for the resolution logic that changes the push target from a fixed `origin` to the current upstream first. An empty stdout from `branch --show-current` is treated as detached HEAD, and the upstream remote / branch is read only when there is a current branch. A valid upstream returns `upstream`, no upstream / detached returns `selectRemote` with the remote list in ascending order, and a failed Git query returns `error`. `getRemotes()` distinguishes a fetch failure (`null`) from 0 remotes (`[]`) with different values. The push args belong to S43, and the host-side phase decision to `src/gitGraphView-test/01-message-routing-03.md` S28.

## S43: pushToUpstream() / pushWithUpstream() running an explicit push

> Origin: Feature 047 (safe-remote-checkout-and-explicit-push) (light-spec-plan)
> Added: 2026-08-03
> Updated: 2026-08-04
> Status: active
> Supersedes: S10
> Signature: `pushToUpstream(repo: string, target: PushTarget): Promise<GitCommandStatus>` / `pushWithUpstream(repo: string, remoteName: string): Promise<GitCommandStatus>`
> Target Path: `src/dataSource.ts` (`pushToUpstream()` / `pushWithUpstream()`; update to a line range after implementation)
> Test File: `tests/src/dataSource.test.ts` / `tests/src/dataSource.git.test.ts`

A change that drops the fixed `["push", "--set-upstream", "origin", "HEAD"]` of `push(repo)`. With an upstream it uses `["push", <remote>, "<localBranch>:<upstreamBranch>"]`, and only registering a new upstream after the choice is confirmed uses `["push", "--set-upstream", <remote>, "HEAD"]`. The refspec separates the local branch being pushed from the upstream branch it is pushed to, so after a rename the current local branch is still sent to the existing upstream. Because `push()` and the origin-fixed args are removed, this supersedes the old S10 that fixed `["push"]` (no arguments) as the current spec. `pull()`, which the old S10 covered in the same section, is out of scope of this change and its behaviour does not change, so it is carried over as S44 and stays active. `fetch()` / `pushTag()` do not change.
