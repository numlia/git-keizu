## S24: viewDiff() resolves HEAD with resolveRefToHash and adds a version query for uncommitted changes

> Origin: フェーズ2 修正 M9/M10 (view-diff-resolve-head)
> Added: 2026-07-04T02:44:58Z
> Status: superseded
> Supersedes: S16
> Superseded By: S47
> Signature: `private async viewDiff(repo, commitHash, oldFilePath, newFilePath, type, compareWithHash?): Promise<boolean>`
> Target Path: `src/gitGraphView.ts:745-800`

A fix that replaces the mutable `HEAD` reference in uncommitted diffs with `dataSource.resolveRefToHash(repo, "HEAD")` (a fixed hash resolved by rev-parse), falling back to `"HEAD"` when it cannot be resolved. The resolved hash builds `actualFromHash` in compare mode (`compareWithHash !== undefined`) and the left URI in the non-compare uncommitted mode (`compareWithHash === undefined` and `commitHash === UNCOMMITTED_CHANGES_HASH`). The right URI on the uncommitted side (type `D`) gets a version query via `encodeDiffDocUri(..., Date.now().toString())` to invalidate the cache. The `try/catch` around the three `vscode.diff` calls (returning `false` on an exception) carries over the perspectives of the old S16. This section replaces the old S16 (which assumed `HEAD` was embedded directly).

For TC-433, an added file replacing a committed directory also has an empty left side.
For a staged BOM-less Shift JIS addition in a folder with its own encoding, the right side displays the saved Japanese text and the raw snapshot retains the original bytes.
On older editors, TC-433 also checks a rejected guess candidate and a closed file whose language depends on its original path. Language detection must work when the full file exceeds the extension host's synchronization limit.
On both older and newer editors, the extension host can process other events while a large file is decoded. Characters that span chunks and an incomplete final byte sequence must match whole-file decoding. Newer editors also retain the encoding selected in an open document or detected for a closed file.
From VS Code 1.140, an inconclusive guess on a non-UTF-8 sample can still select the only configured candidate that reproduces the original bytes. The comparison follows the editor when several candidates match or the sample ends inside a valid UTF-8 character.
