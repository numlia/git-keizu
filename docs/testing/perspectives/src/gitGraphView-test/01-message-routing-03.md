## S28: Phase orchestration of two-step Push

> Origin: Feature 047 (safe-remote-checkout-and-explicit-push) (light-spec-plan)
> Added: 2026-08-03

> Test File: `tests/src/gitGraphView.test.ts`

Perspectives for replacing the single-step call to `dataSource.push(repo)` with mediation over 3 phases (`selectRemote` / `noRemotes` / `completed`) based on the result of `preparePush()`. The first Request (`selectedRemote === null`) only resolves; the second one re-runs `getRemotes()`, re-checks membership and safety, and then calls `pushWithUpstream()`. Every Response carries the original Request's `operationId` unchanged. The old S5 pinned the single-step call to `dataSource.push(repo)` as its expected result, so it is superseded; pull routing, which this change does not touch, is kept as S30. Git args and resolution rules belong to `src/dataSource-test/02-branch-worktree-02.md` S42 / S43, and the webview display and selection UI to `web/messageHandler-test.md` S12 / `web/refMenu-test/01-branch-actions-01.md` S17.
