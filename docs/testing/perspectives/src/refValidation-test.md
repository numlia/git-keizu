## S1: isValidRefName() / isSafeRemoteName() pure validation

> Origin: Feature 047 (safe-remote-checkout-and-explicit-push) (light-spec-plan)

> Test File: `tests/src/refValidation.test.ts`

Perspectives for the pure functions that check, before starting a Git process, the ref names and remote names the host passes to checkout / Push. `isValidRefName()` rejects structures that break the Git ref rules (empty string, leading `-` / `/` / `.`, trailing `.` / `/` / `.lock`, empty segment, segment starting with `.`, `..`, `@{`, whitespace, control characters, characters forbidden by Git). `isSafeRemoteName()` rejects only the empty string and a leading `-` (mistaken for an option); matching against the list of registered remotes is the host's responsibility (`src/gitGraphView-test/01-message-routing-03.md` S28). Input validation on the webview side (`refInvalid` in `web/utils.ts`) is outside this owner; UI validation and host validation have separate responsibilities.
